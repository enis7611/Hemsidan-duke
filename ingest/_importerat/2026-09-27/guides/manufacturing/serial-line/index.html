Serial Production Line

A sequential manufacturing line where items pass through multiple processing stages in order, with a queue before each stage to buffer work-in-process. Models assembly lines, pipeline processes, or multi-step production flows.

When to use this

  • Modeling a manufacturing line with sequential operations (machining, assembly, inspection)
  • Identifying bottleneck stations that limit overall throughput
  • Evaluating the effect of buffer sizes between stations on line performance
  • Analyzing work-in-process inventory levels across the production line
  • Comparing alternative line configurations (rebalancing cycle times across stations)

Blocks

BlockLibraryLabelPurpose
CreateItem.lbrRawMaterialGenerates parts or jobs entering the production line
QueueItem.lbrBuffer1Holds work-in-process waiting for Stage 1; size represents physical buffer capacity
ActivityItem.lbrStage1First processing operation with its own cycle time distribution
QueueItem.lbrBuffer2Intermediate buffer between Stage 1 and Stage 2
ActivityItem.lbrStage2Second processing operation; if slower than Stage 1, becomes a bottleneck
QueueItem.lbrBuffer3Intermediate buffer between Stage 2 and Stage 3
ActivityItem.lbrStage3Third processing operation; final production step before exit
ExitItem.lbrFinishedGoodsCollects completed parts and records overall throughput and cycle time

Connections

  • RawMaterial (ItemOut) → Buffer1 (ItemIn)
  • Buffer1 (ItemOut) → Stage1 (ItemIn)
  • Stage1 (ItemOut) → Buffer2 (ItemIn)
  • Buffer2 (ItemOut) → Stage2 (ItemIn)
  • Stage2 (ItemOut) → Buffer3 (ItemIn)
  • Buffer3 (ItemOut) → Stage3 (ItemIn)
  • Stage3 (ItemOut) → FinishedGoods (ItemIn)

Key parameters

BlockParameterTypicalWhat it controls
Activity (each stage)distribution / arg1Triangular(min, mode, max) or constant per stageCycle time per stage. The slowest stage (highest mean cycle time) is the bottleneck and determines maximum line throughput.
Queue (each buffer)maximum capacity5-20 itemsPhysical buffer size between stations. Larger buffers decouple stations and improve throughput but increase WIP inventory cost.
Createdistribution / arg1Constant, value = bottleneck cycle time or slightly fasterRelease rate into the line. For push systems, set faster than bottleneck. For pull/kanban, use Gate blocks to control release.
ActivitydelayTypefixed or distributionUse 'fixed' for deterministic lines; 'distribution' adds variability. Variability at any stage reduces effective throughput below theoretical maximum.

Common mistakes

  • Omitting Queue blocks between Activity blocks — without buffers, a blocked downstream Activity will also block upstream Activities through back-pressure, which may or may not be intended; always explicitly add Queue blocks and set their capacities to match physical reality
  • Making all stage cycle times equal and expecting perfect throughput — variability at any stage causes blocking and starving even when means are balanced; use realistic distributions (triangular or normal) rather than constants
  • Setting Create inter-arrival time faster than the bottleneck cycle time — the system never reaches steady state and buffers fill indefinitely; the Create rate should not exceed 1/bottleneck_cycle_time
  • Forgetting that the Activity block processes one item at a time by default — if a real machine processes batches, use Batch block before the Activity or set appropriate delay to reflect batch cycle time

What to measure

  • Throughput rate (FinishedGoods items per hour)
  • Station utilization per stage (identify bottleneck as highest utilization)
  • Average WIP inventory in each buffer queue
  • Average total cycle time from raw material to finished goods
  • Buffer overflow frequency (if finite buffer capacity is set)
