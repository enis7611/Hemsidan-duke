Simple Queue (M/M/1)

A single-server queuing system where items arrive randomly, wait in a queue, are processed by one server, and depart. This is the foundational discrete-event pattern for any service or processing system.

When to use this

  • Modeling a single-server service point (cashier, machine, call agent)
  • Analyzing waiting times and queue lengths under variable demand
  • Estimating server utilization and throughput capacity
  • Baseline model before adding complexity like multiple servers or priorities
  • Teaching or demonstrating Little's Law and queuing theory concepts

Blocks

BlockLibraryLabelPurpose
CreateItem.lbrArrivalsGenerates items (customers, jobs) according to an inter-arrival time distribution
QueueItem.lbrWaitingLineBuffers items when the server is busy; tracks queue length and wait time statistics
ActivityItem.lbrServerProcesses one item at a time with a configurable service time distribution
ExitItem.lbrDeparturesRemoves items from the model and records throughput and cycle time statistics

Connections

  • Arrivals (ItemOut) → WaitingLine (ItemIn)
  • WaitingLine (ItemOut) → Server (ItemIn)
  • Server (ItemOut) → Departures (ItemIn)

Key parameters

BlockParameterTypicalWhat it controls
Createdistribution / arg1Exponential, mean=5 minInter-arrival time distribution. Exponential gives Poisson arrivals (M/M/1 assumption). Mean sets average time between arrivals.
Activitydistribution / arg1Exponential, mean=4 minService time distribution. Mean must be less than mean inter-arrival time to keep utilization below 100%.
QueuerankTypeFIFO (0)Item ranking rule. FIFO (first-in first-out) is standard for M/M/1. Change to attribute-based for priority queues.
CreatemaxArrivals0 (unlimited)Maximum number of items to generate. Set to 0 for unlimited (steady-state runs). Limit for finite-population studies.

Common mistakes

  • Forgetting to place a Queue before the Activity — without a Queue, items that arrive when the server is busy are destroyed rather than waiting, causing incorrect throughput and lost-item errors
  • Setting server utilization at or above 100% (mean service time >= mean inter-arrival time) — the queue grows without bound and the model never reaches steady state; always verify utilization = (mean service time / mean inter-arrival time) < 1
  • Running the simulation for too short a time — M/M/1 systems need a warm-up period before reaching steady state; results collected during transient phase are not representative
  • Using a constant (fixed) inter-arrival time instead of exponential when modeling Poisson arrivals — constant arrivals prevent realistic queue buildup and underestimate wait times

What to measure

  • Average queue length (WaitingLine block statistics)
  • Average wait time in queue (WaitingLine block statistics)
  • Server utilization percentage (Server block statistics)
  • Throughput (items per time unit, from Departures block)
  • Average total cycle time (from Departures block)
