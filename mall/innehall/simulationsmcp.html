🔗 Körande ExtendSim via COM

Servern hittar din igångvarande ExtendSim via COM och skickar kommandon direkt. Inga externa API:er — i stdio-läge finns ingen nätverksyta alls.

⏳ Fire-and-forget + polling

Långa simuleringar startar i en bakgrundstråd och returnerar direkt. AI:n pollar simulation_status tills körningen är klar — inga timeouts, realtidsprogress.

🎯 Auto-typdetektering

block_configure läser av blocktypen (Activity, Queue, Tank, Valve …) och skickar parametrarna till rätt internt API. Ett verktyg täcker 25+ blocktyper.

🛡️ Automatisk dialoghantering

En bakgrundsprocess upptäcker och stänger modala dialoger som annars skulle blockera COM-tråden — och läser av feltexten så du vet vad som hände.

All inmatning saneras innan den körs som ModL, och farliga kommandon är blockerade. Telemetrin är lokal och innehåller aldrig modelldata.

Systemkrav

🪟

Windows 10/11 (64-bit)

ExtendSim installerat med registrerad COM-komponent — och igång när du arbetar.

⚙️

Node.js 18+ och Python 3

Med pywin32. Transport via stdio (noll konfiguration) eller HTTP för ChatGPT.

Bra att veta

🔒

Noll nätverksyta i stdio-läge

Ingen port, inga moln-API:er — direkt processlokal kommunikation med ExtendSim.
