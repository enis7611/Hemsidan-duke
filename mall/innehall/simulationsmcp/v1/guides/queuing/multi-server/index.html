🧭 Queuing Systems

Multi-Server Queue (M/M/c)

A queuing system with multiple parallel servers sharing a single waiting line. Items wait in one queue and are routed to the next available server, modeling call centers, bank teller lines, or parallel machines.

Queuing Systems

When to use this

  • Modeling multiple identical servers serving one shared waiting line (e.g., bank tellers, checkout lanes)
  • Finding the optimal number of servers to balance cost against customer wait time
  • Comparing single-queue/multi-server versus multi-queue/single-server configurations
  • Evaluating the impact of adding or removing servers on throughput and utilization
  • Modeling parallel machines or workstations in a manufacturing cell

Common mistakes

  • ⚠️ Using a Workstation block (which has an internal queue) and also placing a separate Queue block before it — this creates two queues in series, inflating wait times and misrepresenting system behavior; use Workstation alone or use separate Queue+Activity blocks
  • ⚠️ Setting maxServers on a Workstation but forgetting that Workstation service time is per item, not shared across servers — each server independently draws from the service distribution
  • ⚠️ Connecting parallel Activity blocks without Select Item Out/In routing — items will only flow to the first connected Activity; use Select Item Out (shortest queue mode) to distribute load correctly when using separate Activity blocks instead of Workstation
  • ⚠️ Not verifying offered load (lambda / (c * mu)) is below 1.0 — with multiple servers the stability condition is different from M/M/1 and is easy to miscalculate

Variations

🔀

Heterogeneous servers

Use separate Queue + multiple Activity blocks with different service time distributions; route via Select Item Out in shortest-queue mode

🔀

Single server baseline →

Set maxServers=1 on Workstation or use a single Activity to establish the M/M/1 baseline for comparison

🔀

Priority multi-server →

Add Set block to assign priorities; configure Workstation or Queue with attribute-based ranking
