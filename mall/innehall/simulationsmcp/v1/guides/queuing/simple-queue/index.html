🧭 Queuing Systems

Simple Queue (M/M/1)

A single-server queuing system where items arrive randomly, wait in a queue, are processed by one server, and depart. This is the foundational discrete-event pattern for any service or processing system.

Queuing Systems

When to use this

  • Modeling a single-server service point (cashier, machine, call agent)
  • Analyzing waiting times and queue lengths under variable demand
  • Estimating server utilization and throughput capacity
  • Baseline model before adding complexity like multiple servers or priorities
  • Teaching or demonstrating Little's Law and queuing theory concepts

Common mistakes

  • ⚠️ Forgetting to place a Queue before the Activity — without a Queue, items that arrive when the server is busy are destroyed rather than waiting, causing incorrect throughput and lost-item errors
  • ⚠️ Setting server utilization at or above 100% (mean service time >= mean inter-arrival time) — the queue grows without bound and the model never reaches steady state; always verify utilization = (mean service time / mean inter-arrival time) < 1
  • ⚠️ Running the simulation for too short a time — M/M/1 systems need a warm-up period before reaching steady state; results collected during transient phase are not representative
  • ⚠️ Using a constant (fixed) inter-arrival time instead of exponential when modeling Poisson arrivals — constant arrivals prevent realistic queue buildup and underestimate wait times

Variations

🔀

Finite queue (blocking)

Set Queue maximum capacity to limit queue length; items that arrive when queue is full are rejected or redirected

🔀

Multiple servers →

Replace single Activity with Workstation (maxServers > 1) or add parallel Activities with Select Item Out/In routing

🔀

Priority service →

Add a Set block before Queue to assign priority attributes; change Queue rankType to attribute-based ranking
