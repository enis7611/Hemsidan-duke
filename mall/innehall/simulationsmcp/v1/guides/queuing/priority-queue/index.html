Priority Queue

A queuing system where items are served in priority order rather than arrival order. High-priority items jump ahead of lower-priority items in the queue, modeling emergency services, VIP lanes, or job scheduling with urgency levels.

Queuing Systems

When to use this

  • Modeling systems where certain customers or jobs must be served before others regardless of arrival order
  • Evaluating the impact of priority classes on wait time distribution across customer segments
  • Modeling preemptive or non-preemptive service disciplines in computer or manufacturing systems
  • Designing triage systems in healthcare, emergency response, or critical systems
  • Analyzing fairness trade-offs: high-priority items get fast service but low-priority items may wait excessively

Common mistakes

  • ⚠️ Setting the Queue sort attribute name that does not exactly match the attribute name assigned by the Set block — the Queue will not recognize the attribute and will default to FIFO, silently ignoring priorities; attribute names are case-sensitive
  • ⚠️ Using ascending sort with higher numbers meaning higher priority — this sorts backwards; either use lower numbers for higher priority with ascending=true, or use descending=true with higher numbers for higher priority
  • ⚠️ Using a single Create block and trying to assign priorities probabilistically inside one Set block — it is cleaner and more accurate to use separate Create blocks with different rates for each priority class so arrival rates are independently controlled
  • ⚠️ Omitting the Set block and trying to assign priority in the Create block itself — Create block does not support attribute assignment; a Set block immediately after Create is required

Variations

Two priority classes (high/normal)

Use two Create blocks with different rates; Set assigns attribute=1 for high, attribute=2 for normal; single Queue with attribute ranking

🔀

Priority with multiple servers →

Replace Activity with Workstation (maxServers > 1); Workstation respects Queue priority ranking when pulling items

Change Queue rankType to FIFO to compare priority discipline versus first-come-first-served performance
