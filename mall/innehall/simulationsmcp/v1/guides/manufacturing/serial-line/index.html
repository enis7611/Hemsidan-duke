Serial Production Line

A sequential manufacturing line where items pass through multiple processing stages in order, with a queue before each stage to buffer work-in-process. Models assembly lines, pipeline processes, or multi-step production flows.

Manufacturing

When to use this

  • Modeling a manufacturing line with sequential operations (machining, assembly, inspection)
  • Identifying bottleneck stations that limit overall throughput
  • Evaluating the effect of buffer sizes between stations on line performance
  • Analyzing work-in-process inventory levels across the production line
  • Comparing alternative line configurations (rebalancing cycle times across stations)

Key parameters

Activity (each stage)distribution / arg1Triangular(min, mode, max) or constant per stageCycle time per stage. The slowest stage (highest mean cycle time) is the bottleneck and determines maximum line throughput.
Queue (each buffer)maximum capacity5-20 itemsPhysical buffer size between stations. Larger buffers decouple stations and improve throughput but increase WIP inventory cost.

Common mistakes

  • ⚠️ Omitting Queue blocks between Activity blocks — without buffers, a blocked downstream Activity will also block upstream Activities through back-pressure, which may or may not be intended; always explicitly add Queue blocks and set their capacities to match physical reality
  • ⚠️ Making all stage cycle times equal and expecting perfect throughput — variability at any stage causes blocking and starving even when means are balanced; use realistic distributions (triangular or normal) rather than constants
  • ⚠️ Setting Create inter-arrival time faster than the bottleneck cycle time — the system never reaches steady state and buffers fill indefinitely; the Create rate should not exceed 1/bottleneck_cycle_time
  • ⚠️ Forgetting that the Activity block processes one item at a time by default — if a real machine processes batches, use Batch block before the Activity or set appropriate delay to reflect batch cycle time

Variations

🔀

Two-stage line

Remove Stage3 and Buffer3 for a simpler two-operation line; useful as a baseline before adding stages

🔀

With inspection and rework →

Add a Select Item Out block after one or more Activity stages to route a percentage of items to a rework Activity

🔀

With shared resources →

Add Resource Pool and have Activity blocks request resources (operators, tools) that are shared across multiple stages
