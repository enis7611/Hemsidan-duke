Shift Schedule

A model where processing capacity changes over time according to a work shift schedule. Activity capacity is linked to a Shift block that defines working hours, breaks, and off-shift periods. Models any operation with scheduled capacity variation.

Resource Management

When to use this

  • Modeling a facility that operates on defined shifts (8-hour, 12-hour, or custom shift patterns)
  • Analyzing queue buildup during off-hours and the clearing time at shift start
  • Evaluating the impact of adding overtime or an additional shift on throughput and backlog
  • Modeling scheduled maintenance windows that take capacity offline periodically
  • Any system where server capacity is a time-varying schedule rather than a fixed number

Common mistakes

  • ⚠️ Not connecting the Shift block output to the Activity capacity connector — the Shift block has no effect on the Activity unless its value output connector is wired to the Activity's capacity input; without this connection the Activity runs at full capacity 24/7
  • ⚠️ Setting shift schedule times in wrong time units — if the simulation runs in minutes but shift start/end times are entered as hours (e.g., 8 instead of 480), the shift pattern will be wildly incorrect; always confirm simulation time units before entering schedule times
  • ⚠️ Forgetting that items already in the Activity when a shift ends continue processing to completion — the shift controls how many new items can start, not whether in-progress items finish; this is usually correct behavior but must be understood when analyzing shift boundary effects
  • ⚠️ Making total daily arrival volume exceed total daily capacity — if arrivals per day consistently exceed (capacity_per_shift * hours_per_shift / mean_service_time), the queue grows unboundedly across days; always verify that daily capacity exceeds daily demand

Variations

🔀

Weekend/weekday schedule

Extend Shift schedule to cover a 168-hour (7-day) cycle with different capacities on weekdays versus weekends

🔀

Shift schedule with shared resources →

Add Shift block to Resource Pool instead of Activity to control the number of available shared resources by shift period

🔀

Overtime trigger

Add an Equation block that monitors queue length and sends a signal to increase Shift capacity above the normal level when backlog exceeds a threshold
