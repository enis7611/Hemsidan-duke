🧭 Resource Management

Shared Resources

Multiple processes compete for a limited pool of shared resources (operators, tools, vehicles). Each process requests resources when needed, uses them during processing, and releases them for other processes to use.

Resource Management

When to use this

  • Modeling operators, technicians, or vehicles shared across multiple production lines or service points
  • Analyzing resource contention and its impact on throughput and waiting time
  • Determining the minimum number of shared resources to achieve a target utilization or wait time
  • Modeling tool cribs, forklifts, or test equipment shared by multiple work centers
  • Any scenario where a finite pool of resources is the primary constraint on system throughput

Resource Management

Common mistakes

  • ⚠️ Forgetting to link the Queue block to the Resource Pool — in ExtendSim, the Queue block (not the Activity block) requests resources; if the Queue's resourcePoolBlockId is not set, resources are never requested and items flow through without resource constraint
  • ⚠️ Connecting the Resource Pool directly to the Activity block instead of to the Queue block — resources must be requested at the Queue so items wait for both server availability AND resource availability; resource request at Activity happens too late
  • ⚠️ Setting resourcesNeeded to a number larger than initialResources — if any process needs more resources than exist in the pool, those items will wait forever and the simulation will deadlock
  • ⚠️ Not including a Queue block before each Activity when using Resource Pool — without a Queue, the resource request linkage cannot be established and resources will not be properly requested or released

Variations

🔀

Priority resource allocation →

Set Queue allocationRule to priority-based and assign priority attributes to items; high-priority items get resources before low-priority items when pool is contended

🔀

Multiple resource types

Add a second Resource Pool for a different resource type (e.g., operator pool + tool pool); Queue requests resources from both pools simultaneously

🔀

With shift schedule →

Add Shift block to Resource Pool to vary resource availability over time (e.g., more operators during day shift than night shift)
